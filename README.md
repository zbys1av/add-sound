## Основний сценарій: після No Pause Allowed

1. Зробіть монтаж і експортуйте готовий **MP4/H.264** у No Pause Allowed.
2. Відкрийте SoundLayer у браузері, на цьому або іншому пристрої, і виберіть готовий файл.
3. Додайте атмосферні звуки, зациклення, плавні переходи, відрегулюйте гучність.
4. Експортуйте новий файл. **Відеопотік копіюється без повторного кодування**, а звук змішується окремо.

SoundLayer не аналізує рух і не змінює монтаж; No Pause Allowed залишається окремим, незміненим проєктом. Передача файлу між програмами — через файлову систему/завантаження, без прихованої інтеграції. No Pause Allowed наразі є Windows-застосунком; браузерна доступність SoundLayer не означає, що весь монтаж автоматично працює на кожному пристрої.

Швидкий експорт (WebCodecs + Mediabunny) працює за підтримки кодеків браузером. FFmpeg.wasm **не запускається автоматично** після помилки швидкого режиму: користувач сам натискає кнопку резервного експорту. Його скрипт завантажується тільки при потребі. На телефоні є обережне обмеження розміру для резервного експорту; підтримка інших форматів не гарантується.

# SoundLayer 2 — браузерний редактор звуку для відео

SoundLayer 2 — статичний вебзастосунок HTML/CSS/JS. Працює **без Python, Node.js, .exe, сервера з обробкою відео чи інсталяції програм**. Користувацькі відео й аудіофайли залишаються в його браузері.

## Розміщення на GitHub Pages

1. Створіть порожній репозиторій GitHub, наприклад `soundlayer`.
2. Завантажте **весь вміст архіву** в корінь репозиторію (файли `index.html`, `app.js`, `style.css`, `fast-export.js`, `README.md`, `.nojekyll` і каталог `assets/`). Не завантажуйте ZIP як один файл.
3. У **Settings → Pages → Build and deployment** виберіть **Deploy from a branch → main → /(root) → Save**.
4. Відкрийте посилання, яке покаже GitHub Pages, наприклад `https://USER.github.io/soundlayer/`.

При відкритті `index.html` через `file://` попередній перегляд може працювати, але CORS і Web Workers заважають експорту; GitHub Pages рекомендовано. Статичний хостинг достатній, бекенд не потрібен.

## Зміни у версії 2

- Прибрано великий заголовок, логотип і вступний блок; інтерфейс починається з редактора.
- Діагностика браузера: сповіщення про Firefox, Safari та відсутні WebCodecs/Web Audio/WebAssembly/Workers. Попередження не означає, що всі браузери гарантовано не працюють.
- Прямі посилання HTTPS на аудіофайли з CORS можна додати у проєкт; файл має мати розширення `.mp3`, `.ogg`, `.wav`, `.opus`, `.m4a`, `.aac` або `.flac` і бути не більшим за 50 МБ.
- YouTube URL відображається для перегляду вбудованим плеєром; **витягування чи завантаження звуку YouTube не реалізоване**. Для монтажу використовуйте файл, який маєте право використовувати.
- Вбудовані звуки тепер використовують реальні записи з Wikimedia Commons — дощ, горіння, вітер, хвилі, лісові птахи та вода. Вони завантажуються під час прослуховування/експорту. Якщо запис недоступний, залишається локальний синтезований запасний звук. Отже для якісної бібліотеки потрібен інтернет; відтворення та експорт віддалених звуків можуть залежати від CORS/CDN.
- Для браузерів із потрібними кодеками ввімкнено швидку обробку **Mediabunny 1.65.0**: закодовані пакети відеопотоку копіюються, змішаний звук кодується через WebCodecs. Відео не декодується й не кодується заново.
- Якщо швидкий режим не підтримує ваш формат/кодек, застосунок пробує резервний **FFmpeg.wasm** (`-c:v copy`). Він відчутно повільніший і використовує більше оперативної пам’яті. Деякі файли через це неможливо обробити у браузері.
- Додаткове SHA-256 порівняння відеопотоків вимкнене за замовчуванням, щоб не виконувати два зайвих проходи по файлу. Увімкнення примусово запускає повільніший FFmpeg-режим. Якщо порівняння недоступне, інтерфейс прямо повідомляє про це.
- Не використовується `-movflags +faststart` при запасному експорті, щоб уникати додаткового проходу по великому MP4.

## Функції

- Імпорт відео та декількох доріжок із файлів, бібліотеки чи прямих HTTPS URL.
- Гучність, початок, тривалість, зациклення, fade-in / fade-out кожної доріжки.
- Автоматичне розставлення звукових доріжок із перехідними згасаннями.
- Попередній перегляд у браузері.
- Експорт зі збереженням оригінальних закодованих відеопакетів за наявності підтримки. Звукова доріжка формується окремо.

## Обмеження та швидкодія

- **Не всі кодеки/контейнери підтримуються у швидкому режимі.** Chrome/Edge зазвичай дають ширші можливості WebCodecs, але конкретна підтримка AAC, Opus, H.264/HEVC/AV1 залежить від пристрою та браузера. Firefox і Safari можуть перейти до FFmpeg.wasm; застосунок повідомляє про це.
- Для швидкого MP4 потрібен доступний браузерний енкодер AAC; для WebM — Opus. Вихідний відеокодек повинен поміщатися у вибраний контейнер, інакше застосунок пробує резервний режим без перекодування.
- Відеофайли великого розміру навіть у швидкому режимі потребують оперативної пам'яті. FFmpeg.wasm має практичну межу у поточному коді — 450 МБ на вхідне відео. Це програмне обмеження від ризику переповнення пам’яті, не універсальна межа технології.
- **Збереження якості:** відеокадри не перекодовуються. Кодек, роздільність і фактичні кодовані пакети зберігаються, коли експортування вдалося, але контейнер, метадані, субтитри та деякі службові характеристики можуть відрізнятися. Для максимального контролю увімкніть SHA-256 (займає більше часу); навіть тоді перевірка можлива не в усіх форматах.
- При експорті змішаного аудіо воно кодується повторно. Плавність на стиках коротких зациклених звуків може відрізнятися між попереднім переглядом та фінальним експортом.
- Для першого швидкого експорту потрібен інтернет (Mediabunny завантажується з CDN). FFmpeg.wasm (~32 МБ) завантажується тільки при потребі резервного способу; CDN може бути заблокований розширеннями браузера або мережею.
- Ні GitHub Pages, ні сторонній сервер не отримують надіслані користувачем відео або аудіо. Сайт **звертається по зовнішні JS-бібліотеки та бібліотечні природні звуки**. Додавання аудіо за прямим посиланням означає запит до зазначеного сайту.

## Перевірка

Перевірено синтаксис JavaScript, інтерфейс Chromium (імпорт відео/аудіо, налаштування доріжок, попередження, URL-поле) та команди `-c:v copy` у звичайному FFmpeg: хеші кодованих відеоданих збігаються на тестових MP4/WebM. **Повний реальний експорт через Mediabunny або FFmpeg.wasm, завантажені з CDN у браузері, не вдалося протестувати через обмеження доступу до CDN в тестовому середовищі**; реальний браузер на GitHub Pages потрібен для фінальної перевірки сумісності.


## FFmpeg startup / оптимізація

- Резервний рушій FFmpeg завантажується тільки якщо швидкий режим недоступний або обрано SHA-256 перевірку.
- Після першого завантаження компоненти зберігаються в браузерному Cache Storage (`soundlayer-ffmpeg-core-0.12.10-v1`). Наступні запуски використовують кеш, якщо його не очищено.
- Завантаження показує отримані мегабайти, відсоток та окремий етап ініціалізації WebAssembly; через 120 секунд без відповіді показується помилка замість нескінченного очікування.
- **Перший запуск все одно потребує завантаження близько 32 МБ** і компіляції WebAssembly, тому миттєве відкриття гарантувати неможливо. Найшвидший експорт у Chrome/Edge із доступним WebCodecs; опцію SHA-256 слід вмикати тільки для спеціальної перевірки, бо вона вмикає FFmpeg.
- Якщо кеш недоступний через приватний режим / обмеження браузера, програмою можна користуватися, але компоненти завантажуватимуться повторно.
